# HTTP 转发抓包服务

把设备的 HTTP 请求原样转发到真正的服务器，并把「设备发了什么、服务器回了什么」全部打印到窗口日志里，用于排查设备与服务器之间的通讯是否正常。

```
设备  ──HTTP──▶  本程序（本机 8089）  ──HTTP / HTTPS──▶  远程服务器
                    │                                        │
                    └──────── 全部请求/响应内容写入彩色日志 ◀──┘
```

## 一、文件说明

| 文件 | 用途 |
| --- | --- |
| `HTTP转发服务.exe` | 打包好的程序，双击即用（自带 Python 运行时，目标机不用装 Python） |
| `HTTP转发服务.pyw` | 界面源码 |
| `forwarder.py` | 转发抓包核心源码（收发、解析、日志，界面无关） |
| `app_icon.ico` | 程序图标 |
| `forwarder_config.json` | 连接配置，**首次启动后自动生成**，删除即恢复默认 |
| `logs\` | 日志文件目录，**启动后自动创建**，按日期一天一个 `.log` 文件 |

## 二、快速使用

1. 双击 `HTTP转发服务.exe`（单文件自解压，首次启动约 3~8 秒，属正常现象）。
2. 填写远程参数：
   - **本地监听端口**：默认 `8089`，就是设备要连的端口；
   - **远端协议**：`http`（默认）或 `https`；
   - **远程服务地址**：服务器的 IP 或域名，如 `192.168.1.10` 或 `api.example.com`；
   - **远程服务端口**：http 默认 `80`，https 默认 `443`（切协议会自动带出，可改）。
   窗口标题栏会直接显示本机 IP 与监听端口，如 `HTTP 转发抓包服务 —— 监听中 192.168.0.172:8089`（多网卡时取默认出口网卡，一般就是与设备同网段的那块）。
3. 点【启动服务】。按钮变灰、状态栏亮绿点即运行中；再点【停止服务】停止接收。
4. 设备侧配置：HTTP 服务地址填**运行本程序的电脑的局域网 IP**（窗口右下角会直接提示，例如 `http://192.168.172.180:8089`），端口填本机监听端口。
5. 设备发请求时，日志会按原始报文的样子滚动输出（请求行+头+正文 → 响应行+头+正文 → 耗时），并**同时写入 `logs` 目录下的日志文件**。

启动时会**自动保存**上面四项配置，下次打开程序**自动载入**（包括上次选中的协议）。

## 三、日志说明

日志按**原始报文**的样子平铺输出，不加任何分类标签，每段报文只有首行带时间戳：

```
[15:51:55.278] 收到：192.168.0.172 >POST /hpt/v1/CurrentTime HTTP/1.1
user-agent: HPT-Machine
connect: close
client-id: 0002
DevTime: 2026-11-11 15:51:56
sn: RY202308230159
Content-Type: application/json; charset=utf-8
Accept-Encoding: gzip
Host: 192.168.0.172:8088
Content-Length: 24
Connection: close

{"ICCID":"","ICCID2":""}
[15:51:55.290] 返回：HTTP/1.1 200 OK
content-encoding: gzip
server: Microsoft-HTTPAPI/2.0
content-type: application/json; charset=utf-8
content-length: 201

{"Status":"100","Msg":"","CloseTime":null,...}
[15:51:55.298] 耗时 20 ms（服务器往返 20 ms） · 上传 24 字节 / 下载 201 字节
```

- `[15:51:55.278]` 是「时:分:秒.毫秒」；
- `收到：设备IP >请求行` 表示设备发来的请求（`>` 指向服务器）；`返回：状态行` 表示服务器的响应；
- 头部与正文之间、每段报文之间（请求块 ↔ 响应块、正文 ↔ 耗时行）都留一空行分隔，不会挤成一片；
- 响应被 gzip 压缩时，正文之后空一行再给括号注释；
- 头部按服务器/设备**原始大小写、原始顺序**逐行输出，一行空行之后就是正文，文本正文原样贴出、不缩进；
- 文件和图片不打印内容，只输出一行 `二进制数据 45231 字节（JPEG 图片）`；
- gzip/deflate 压缩的响应会解压后显示明文，并在正文末尾用括号注明「已解压 gzip：201 字节 → 明文 300 字节」；设备收到的仍是原始压缩数据；
- 正文超过 6000 字符会截断并注明；
- 说明：日志里显示的是**设备原始请求头**（含原始 Host），实际转发时 Host 会被改写成真正的目标地址。

颜色仍保留：蓝灰=连接/系统、青绿=收到的请求、浅蓝=返回的响应、灰=头部、白=正文、黄=二进制、绿=耗时、**红=错误**。

红色具体覆盖这几种情况（都是为了让你一眼找到出问题的那一处）：

- 连不上服务器、连接/响应超时、服务器断开：`转发到 http://… 失败：…`；
- 转发失败时我们回给设备的那个 502：`返回给设备 192.168.0.251:33892：HTTP/1.1 502 Bad Gateway（转发失败，…）`；
- **服务器返回 4xx/5xx 状态码**时，`返回：HTTP/1.1 500 Internal Server Error` 这一行本身是红的（正文和头部仍按正常颜色，方便看内容）；
- 读取设备请求失败、回写给设备失败、监听端口失败。

服务器正常返回 2xx/3xx 时响应行是浅蓝，不会误标红。设备空闲超时（60 秒没发数据）用黄褐色提示，属于提示而非错误。

工具按钮：**清空日志**、**导出日志**（存成 txt，含时间戳，便于发给别人看）、**暂停日志输出**。

勾选【暂停日志输出】后：

- 日志框**停止接收新内容**，画面冻结，可以安心上下滚动查看已经有过的请求；
- 转发服务**照常工作**，设备与服务器的通讯不受影响，状态栏的“已处理请求”仍会增长；
- 暂停期间的日志只是**不显示在日志框**，**照样写进 logs 目录的日志文件**（详见下面的「日志文件」）；
- 日志区标题会显示黄字 `● 已暂停接收`；取消勾选即恢复，并提示「已恢复日志输出，暂停期间有 N 条日志未显示（均已写入日志文件）」。

这是排查流量时最常用的操作：抓包时日志刷得太快看不清，先勾上暂停，翻看完再放开。

### 日志文件（自动保存）

程序启动后会自动把日志写进**程序所在目录的 `logs` 子目录**，按日期分文件、同一天持续追加：

```
HTTP转发服务\
├── HTTP转发服务.exe
├── forwarder_config.json
└── logs\
    ├── HTTP转发服务-2026-11-11.log
    └── HTTP转发服务-2026-11-12.log
```

- 文件名里的日期是**记录日期**，跨过零点会自动换新文件，不覆盖前一天的内容；
- 格式与界面完全一致：首行带 `[16:08:55.308]` 时间戳，头部/正文行原样、不带时间戳；
- 文件是 **UTF-8 带 BOM、CRLF 换行**，Win7 记事本直接双击打开也不会乱码、不会连成一行；
- **界面上的「暂停日志输出」「清空日志」只影响屏幕显示**，日志文件始终照常写入 —— 所以哪怕你为了看清某一段而暂停了界面，事后仍可以从文件里补齐这段时间的全部流量；
- 每次启动都会写一行 `日志文件：logs\HTTP转发服务-2026-11-11.log`，方便确认当前写到哪个文件；
- 日志文件不会自动删除，占用变大时手动清理 `logs` 目录即可（建议排查完保留需要的、其余删掉）；
- 如果程序放在只读目录（例如 Program Files），`logs` 建不出来，状态栏/日志区会提示「日志文件写入失败」，此时日志只显示在界面。

## 四、实现要点

- 逐条解析请求行、所有请求头、`Content-Length` 正文与 `Transfer-Encoding: chunked` 正文；
- 支持 `Connection: keep-alive` 连续请求、`100-continue`、`204/304/HEAD` 无正文、分块响应；
- 文本自动识别 UTF-8 / GB18030（GBK 乱码时按 gb18030 解）；
- 响应为 gzip/deflate 压缩时，日志里解压后显示明文（回给设备的仍是原始压缩字节，不改变通讯）；
- `Content-Encoding`/`Transfer-Encoding` 等逐跳头做规范化处理，正文长度统一重算，保证设备端一定能正确收包；
- **转发时会把 `Host` 改写成真正的目标地址**（设备里填的是本机 IP，原样透传服务器多半看不懂）；日志里显示的是设备原始 Host，改写这一步不再额外插提示行，以免打断报文阅读；
- **日志双通道**：界面显示与 `logs` 日志文件独立，暂停/清空只影响界面，文件照常追加；
- https 转发跳过证书校验，自签名证书的服务器也能转发（内网设备常见）；
- 二进制按文件头识别：JPEG/PNG/GIF/BMP/WEBP/PDF/ZIP(APK/Office)/RAR/GZIP/MP4/MP3/WAV 等。

## 五、兼容性（Win7 重点）

程序是用 **Python 3.8（最后一个支持 Windows 7 的 Python 版本）** 打包的，因此：

- Windows 7 SP1（64 位）、Windows 8/10/11 —— 可直接双击运行，**无需安装 Python**；
- 已核对 exe 的 PE 子系统版本为 `6.0`（低于 Win7 的 6.1），且没有依赖 Win8 才有的 `api-ms-win-core-path-l1-1-0.dll`（Python 3.9+ 打包的程序在 Win7 上正是卡在这个依赖上），所以 Win7 SP1 可以加载；
- Win7 若提示缺少 `api-ms-win-crt-*.dll` / `ucrtbase.dll`，安装系统补丁 **KB2999226（Universal C Runtime）** 或 VC++ 2015-2022 运行库即可（一般打过补丁的系统都有）；
- 当前 exe 是 **64 位**。如果目标电脑是 32 位 Win7，需要另打包 32 位版本（告知即可）；
- 单文件 exe 偶尔会被杀软/Defender 拦截，加入信任即可；也可以直接用源码运行：装 Python 3.8+ 后双击 `HTTP转发服务.pyw`。

## 六、常见问题

| 现象 | 处理 |
| --- | --- |
| 点启动提示端口被占用 | 换监听端口（如 8090），或结束占用 8089 的进程 |
| 日志出现 `[错误] 转发到 ... 失败：timed out` | 远端地址/端口填错，或本机到服务器网络不通；先用浏览器或 curl 直接访问服务器验证 |
| 设备没反应 | 确认设备填的是**本机局域网 IP**（不是 127.0.0.1），且和本机在同一网段；Windows 防火墙需放行该端口 |
| 只看到请求没有响应 | 服务器没回包或连接被网络设备中断，日志里会有对应错误行 |
| 想抓 https 的明文 | 本工具是“透明转发”，不做中间人解密，只记录 http 明文；https 只记请求/响应头与字节数，正文为密文 |
